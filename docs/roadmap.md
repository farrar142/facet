# 로드맵

facet을 spec 19개로 나눠 만든다. 각 spec은 끝났을 때 직접 써 보고 확인할 수 있는 단위다. 용어는 `GLOSSARY.md`, 큰 결정의 이유는 `docs/adr/`에 있다.

## Spec 여러 개에 걸친 결정

### UI 프로세스는 하나다

- 모든 창을 UI 프로세스 하나가 띄운다. facet을 다시 실행하면 이미 떠 있는 프로세스에 창 하나를 더 요청하고 끝난다.
- 창을 닫아도 작업은 계속된다. 마지막 창을 닫았는데 작업 대기열에 작업이 남아 있으면 진행 표시만 남기고, 끝나면 프로세스를 종료한다.
- 작업이 없으면 마지막 창과 함께 종료한다. 백그라운드에 상주하지 않는다.

### 단축키는 탐색기와 같게 둔다

- 기본 단축키는 탐색기와 같다. 탐색기에 없는 동작은 탐색기가 쓰지 않는 키에 놓는다.
- 모든 동작은 명령으로 만들고, 단축키·메뉴·명령 팔레트는 그 위에 얹는다.

### 폴더 열기 가로채기는 선택 사항이다

- 기본은 탐색기와 나란히 쓰는 별도 앱이다.
- 설정에서 켜면 Win+E와 폴더 열기를 facet으로 돌리고, 끌 때와 제거할 때 원래대로 복구한다.
- 다른 앱이 항목을 선택한 채로 폴더 열기를 요청하면 그 항목을 선택해 보여 준다.
- 바탕 화면, 작업 표시줄, 파일 열기·저장 대화상자는 건드리지 않는다.
- 비공식 레지스트리 변경이라 Windows 업데이트 뒤에 풀릴 수 있다.

### 속도는 두 군데서 지킨다

- **코어는 CI가 지킨다.** 화면 없는 코어(10만 항목 목록 읽기·정렬·필터, 인덱스 질의, 복사 처리량)는 CI에서 벤치마크를 돌리고, 러너 편차를 감안한 넉넉한 상한을 넘으면 실패시킨다. 10배 느려지는 실수를 잡는 용도다.
- **화면 수치는 사람이 잰다.** 콜드 스타트와 스크롤 프레임은 측정 명령 하나로 만들어 두고, spec이 끝날 때마다 사람이 자기 기계에서 돌려 기록한다.
- 티켓마다 그 변경이 닿는 속도 기준을 수용 조건에 적는다.

# 주소창 › 펼침 메뉴 사람 확인 목록

화면은 자동 테스트하지 않는다. `crates/facet-app/src/crumb_menu.rs`(상태·키·자리·넘기기)는 단위 테스트가 확인하고, 아래는 사람이 Windows 기계에서 확인한다(#306).

1. `cargo run -p facet-app -- C:\Windows\System32`로 띄운다. 주소창 조각 `Windows` 뒤의 ›를 누르면 그 아래에 `C:\Windows`의 하위 폴더 메뉴가 열리고 `System32` 줄이 굵다. 파일은 없다. › 단추를 다시 누르면 닫힌다.
2. 메뉴에서 ↓·↑로 줄을 고르면 강조가 움직이고 끝에서 돈다(고른 줄이 늘 보인다). Enter면 그 폴더로 가고 Alt+←로 돌아온다. 줄을 눌러도 같다. Esc·바깥 누르기는 아무 데도 가지 않고 닫는다.
3. 메뉴가 열린 채 다른 조각의 ›로 마우스를 옮기면 그 조각의 메뉴로 바뀐다(패널이 둘이면 다른 패널의 ›도).
4. `C:\Windows\WinSxS`처럼 하위 폴더가 아주 많은 폴더의 ›를 열고 휠로 끝까지 넘긴다. 끊김이 없다.
5. 느린 네트워크 공유(또는 닿지 않는 `\서버\공유`) 조각의 ›를 누르면 곧바로 「읽는 중」 줄이 보이고 그동안 창을 옮기고 다른 탭을 눌러도 멈추지 않는다. 닿지 못하면 까닭 줄이 보인다.
6. 숨김 항목 보이기(Ctrl+H)를 끄고 켜며 `C:\` 조각의 ›를 열면 `$Recycle.Bin`·`System Volume Information` 같은 숨김·시스템 폴더가 설정을 따라 빠지고 나온다.
7. 검색 결과 위치(Ctrl+F로 검색)에서 검색한 폴더 조각까지는 ›가 있고 검색어 조각 뒤에는 없다.
8. 하위 폴더가 없는 폴더의 ›는 「하위 폴더가 없습니다」 줄을 보인다. 조각 뒤의 빈 곳을 누르면 전처럼 주소를 고쳐 쓴다.
9. (#308) 주소창 맨 앞(첫 경로 조각 앞)의 ›를 누르면 드라이브(`C:` 등, 문자 순서)와 사용자 홈 폴더 줄(「(홈 폴더)」 표시)이 열리고 지금 탭의 드라이브가 굵다. 모든 볼륨 즉시 검색 위치처럼 조각이 검색어 하나뿐이어도 맨 앞 ›가 있다.
10. USB 드라이브를 꽂은 뒤 맨 앞 ›를 다시 열면 그 드라이브 문자가 목록에 있다.
11. 다른 드라이브 줄을 누르면 그 드라이브 루트로, 홈 줄을 누르면 홈 폴더로 가고 Alt+←로 원래 위치에 돌아온다. Enter로 골라도 같다.
12. 맨 앞 ›의 메뉴가 열린 채 조각 사이 ›로 마우스를 옮기면 그 메뉴로 바뀌고, 다시 맨 앞 ›로 옮기면 돌아온다. ↓·↑·Enter·Esc는 조각 사이 › 메뉴와 같다.

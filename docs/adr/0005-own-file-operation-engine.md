# 0005. 파일 작업은 자체 엔진이 실행하고, 휴지통만 셸에 맡긴다

- 상태: 채택
- 날짜: 2026-11-15

## 맥락

복사·이동·삭제·이름바꾸기를 셸의 `IFileOperation`에 맡기면 충돌 대화상자, 휴지통, 권한 상승을 그대로 얻는다. 그 대신 느린 준비 단계와 창마다 따로 뜨는 진행 창이 따라오고, 대기열·일시정지·정밀한 실행취소를 만들 수 없다.

## 결정

- 복사·이동·이름바꾸기는 자체 엔진이 하나의 작업 대기열에서 실행한다.
- 모든 작업을 자체 작업 기록에 남기고, 실행취소는 이 기록을 되돌린다.
- 휴지통으로 삭제하기와 휴지통에서 복원하기만 셸에 맡긴다.

## 검토한 대안

- **전부 `IFileOperation`**: 가장 안전하고 구현이 적지만 파일 작업에서 속도 차별점이 사라진다.
- **먼저 `IFileOperation`, 나중에 교체**: 실행취소와 진행 표시를 두 번 만들게 된다.

## 결과

- 데이터를 잃을 수 있는 코드를 직접 책임진다. 이름 충돌, 긴 경로, 잠긴 파일, 권한 거부, 중간 실패 복구를 모두 다뤄야 하고, 이 부분의 테스트가 가장 두꺼워야 한다.
- 권한 상승이 필요한 작업(보호된 폴더에 쓰기)은 따로 설계해야 한다.
- 탐색기의 실행취소 기록과는 이어지지 않는다.

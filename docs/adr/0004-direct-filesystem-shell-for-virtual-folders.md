# 0004. 실제 폴더는 파일 시스템으로 직접 읽고, 가상 폴더만 셸로 읽는다

- 상태: 채택
- 날짜: 2026-11-15

## 맥락

Windows 탐색기는 모든 위치를 셸 네임스페이스(`IShellFolder`)로 읽는다. 가상 폴더까지 한 방식으로 다루지만 항목마다 COM 호출이 끼어 큰 폴더에서 느리다. 파일 시스템 API를 직접 부르면 10만 항목도 수십 ms에 읽지만 가상 폴더는 볼 수 없다.

## 결정

위치를 읽고 조작하는 방법을 공급자로 나눈다.

- **파일 시스템 공급자**: 로컬, 네트워크, 동기화된 클라우드 폴더 같은 실제 경로를 파일 시스템 API로 직접 읽는다.
- **압축 파일 공급자**: zip 내부를 자체 리더로 읽는다.
- **셸 공급자**: 내 PC, 휴지통, MTP 같은 가상 폴더만 셸 네임스페이스로 읽는다.

## 검토한 대안

- **전부 셸 네임스페이스**: 호환성은 완벽하지만 탐색기와 같은 이유로 느리다(ADR-0002와 충돌).
- **파일 시스템 직접만**: 휴지통, 휴대폰, 내 PC 화면이 없어 탐색기를 대체하지 못한다.

## 결과

- 공급자마다 정렬 열, 아이콘, 지원하는 작업이 다르다. 목록 화면은 이 차이를 한 모델로 맞춰야 한다.
- 파일 시스템 공급자의 목록은 탐색기와 다르게 보일 수 있다(숨김 처리, `desktop.ini`의 표시 이름, 라이브러리 등). 차이가 드러나면 그때 맞춘다.

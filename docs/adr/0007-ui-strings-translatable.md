# 0007. 화면 문자열은 처음부터 번역할 수 있게 둔다

- 상태: 채택
- 날짜: 2026-11-15

## 맥락

S0~S18 어디에도 다국어 지원이 없다. 그런데 S1 티켓들이 첫 화면의 문자열을 지금 만들고 있다. 문자열을 코드 곳곳에 박아 둔 채 나중에 다국어를 넣으면, 그때까지 만든 화면을 전부 다시 손대야 한다.

## 결정

대표 결정(2026-11-15): **틀은 지금 만들고, 번역은 나중에 한다.**

- 원문 언어는 한국어다. 지금은 한국어만 낸다.
- `.slint`에서 사용자에게 보이는 글자는 모두 `@tr("…")`로 감싼다. 숫자나 이름처럼 끼워 넣는 값은 `@tr("{} 항목", n)`처럼 자리표시로 넣고, 문장을 이어 붙이지 않는다. 개수에 따라 말이 바뀌는 곳은 `@tr("{n} 항목" | "{n} 항목" % n)` 같은 복수형 문법을 쓴다.
- 코어(`facet-core`)는 화면에 나갈 문장을 만들지 않는다. 명령은 바뀌지 않는 ID를, 오류는 종류(enum)와 값을 돌려준다. 그것을 문장으로 바꾸는 일은 앱 쪽이 하고, 그 문장도 번역 대상이다.
- 앱의 Rust 코드에서 만드는 문장(명령 이름, 오류 문장 등)은 한 모듈에 모아 둔다. 번역 방식이 정해지면 이 모듈 하나만 바꾼다.
- 번역하지 않는 것: 파일·폴더 이름, 경로, 사용자가 친 글자, 로그.

## 미룬 것

번역 파일 형식(Slint 내장 번역과 gettext 중 무엇을 쓸지), 언어 고르기(시스템 언어를 따를지, 설정으로 고를지), 영어 번역은 별도 spec(「다국어」)에서 정한다.

## 결과

- 지금 드는 비용은 문자열을 `@tr()`로 감싸는 것뿐이다.
- 번역 spec에서는 화면을 다시 손대지 않고 번역 파일과 언어 고르기만 더한다.
- 코어가 문장을 만들지 않으므로 코어 테스트는 언어와 무관하다.

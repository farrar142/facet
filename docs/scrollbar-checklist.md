# 스크롤 막대 사람 확인 목록

화면은 자동 테스트하지 않는다. 썸 길이·자리, 썸 끌기, 트랙 누르기의 식은 `crates/facet-app/src/scrollbar.rs`의 단위 테스트가, 가로로 넘긴 목록의 사각형 선택 자리는 `src/marquee.rs`의 단위 테스트가 확인한다. 아래는 사람이 Windows 기계에서 확인한다(#372).

1. `cargo xtask test-folder`로 10만 항목 시험 폴더를 만들고 `cargo run --release -p facet-app -- %TEMP%\facet-test-folders\items-100000`으로 띄운다. 목록 오른쪽에 트랙과 썸이 늘 보이고(마우스를 올리지 않아도) 목록 위에 덮이지 않는다.
2. Windows 설정에서 밝은 모드·어두운 모드를 바꿔 가며 띄운다. 두 모드 모두 트랙과 썸이 바탕과 구별되고, 썸에 마우스를 올리면 진해지고 누르면 더 진해진다.
3. 맨 위에서 썸은 트랙 맨 위에 있고 최소 길이(20px)로 잡을 수 있다. End를 누르면 썸이 트랙 맨 아래에 닿고 마지막 행이 다 보인다. Home이면 맨 위로 돌아온다.
4. 썸을 끌면 목록이 따라 움직이고 끝까지 끌면 마지막 행, 맨 위까지 끌면 첫 행이 보인다. 끄는 동안 마우스가 막대 밖으로 나가도 계속 따라간다.
5. 썸 아래 트랙을 한 번 누르면 한 화면만큼 내려가고, 위 트랙을 누르면 한 화면 올라간다. 누르고 있으면 잠깐 뒤 계속 넘어가다 썸이 누른 자리에 닿으면 멈춘다(지나쳐 거꾸로 가지 않는다).
6. 막대 위에서 휠을 굴리면 목록이 넘어간다. 행이 적어 다 보이는 폴더(빈 폴더 포함)에서는 세로 막대가 없고 목록이 그 자리까지 넓다.
7. 열 경계를 끌어 이름 열을 넓혀 목록보다 넓게 만들면 목록 아래에 가로 막대가 생긴다. 가로 막대를 끌거나 트랙을 누르거나 가로 휠(터치패드 가로 밀기)·Shift+휠을 쓰면 목록이 가로로 넘어가고 열 머리글이 같은 만큼 넘어가 열 경계가 맞는다. 열을 다시 좁히면 가로 막대가 사라진다. 두 막대가 함께 있으면 오른쪽 아래 구석이 비어 있고 막대가 겹치지 않는다.
8. 가로로 넘긴 상태에서: 빈 곳을 끌어 사각형 선택을 하면 사각형이 끈 자리에 그려지고 걸친 행이 골라진다. F2 이름 입력란 까닭 풍선이 이름 칸 근처(보이는 영역 안)에 뜬다. 오른쪽 클릭 메뉴가 누른 자리에 열린다. 다른 앱에서 파일을 끌어 폴더 행 위에 놓으면 그 행이 강조된다.
9. Ctrl+백슬래시로 패널을 나눈다. 두 패널이 저마다 막대를 갖고 한쪽 막대를 끌어도 다른 패널은 움직이지 않는다. 검색 결과 위치(위치·일치 열이 더해짐)에서도 가로 막대와 머리글이 맞는다.
10. `cargo xtask measure`를 돌려 스크롤 프레임 최악값이 기준(한 프레임 시간의 두 배 이하)을 지키는지 본다.
